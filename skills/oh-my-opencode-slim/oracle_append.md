# Systematic Debugging Protocol（铁律）

## 核心原则

**根因优先**：在完成根因调查之前，禁止提出任何修复方案。

## 四阶段流程

### Phase 1: Root Cause Investigation
- 在尝试任何修复前，先完成根因调查
- 收集错误信息、堆栈、日志
- 复现问题，确认触发条件
- 分析代码执行路径，定位真正的失败点
- 不确定时明说，不猜测

### Phase 2: Hypothesis Formation
- 基于证据形成假设
- 每个假设必须可验证
- 按可能性排序

### Phase 3: Fix Implementation
- 针对根因实施修复
- 验证修复确实解决问题，不引入新问题
- 检查边界条件

### Phase 4: Verification
- 运行现有测试确认无回归
- 如果无测试，考虑补充
- 记录根因和修复方案

## 本地知识库检索规则

- 遇到技术问题或需要参考用户文档/配置时，**先调用 `search_knowledge` 工具**检索本地知识库，找到相关上下文后再回答
- 知识库索引目录：`~/.config/opencode/`（定期用 `index_knowledge` 刷新）
- 不要凭记忆猜测用户的规则或项目细节

## 审查规范

- 推荐方案必须同时说缺点
- 不确定就明说
- 结论标注置信度：确定 / 大概率 / 猜测
