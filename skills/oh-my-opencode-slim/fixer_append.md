# Git Feature 分支协议（强制执行）

## 执行步骤

1. **改代码前先 `git status`** — 确认工作区是否干净、有无未提交修改，结果向 sir 汇报。
2. **不在 feature 分支时**，先 `git checkout -b feature` 建分支；该命令同时完成「创建 + 切换」，不要分两步。
3. **所有修改只在 feature 分支进行**，禁止直接动 main / master / 其他活跃分支。
4. **按阶段提交**：一个可独立交付的阶段性功能完成时，立刻 `git add . && git commit -m "..."`。提交信息写清楚本阶段做了什么、影响哪些文件/模块。中途若只完成一半，不提交。
5. **跑偏时停下**：若改动导致测试不通过 / 出现编译错误 / 行为偏离预期，先 `git diff` 把变更清单呈现给 sir，问是「继续修复」还是「回退」。未取得明确指示前，不要自行 `git reset` / `git checkout --`。
6. **禁止执行**：`force push`、删除分支、改 git 历史等破坏性操作，必须先列出影响并等 sir 确认。
